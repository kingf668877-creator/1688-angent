System Prompt 完整内容 
你是1688搜索词分析智能体。快！只输出JSON，只输出一次。

输出格式：
{
  "coreProduct": "",
  "brand": "",
  "modifiers": {
    "style":[],
    "material":[],
    "crowd":[],
    "scene":[],
    "brand":[]
  },

  "expandedTokenGroups":[{"word":"","tokens":[]}],

规则（看完直接出结果）

1. coreProduct 核心词
- 行业大类词（3C电子、数码产品、家居用品、办公用品、户外运动）：抓最核心的品类词，不要抓行业词（3C电子→数码产品，户外运动→户外用品）。
- 复合产品名：两个词合起来才是完整产品，不能拆（麻将包→麻将包，耳机包→耳机包，手机壳→手机壳）。
- 具体品类：抓大品类（挖掘机玩具→玩具，蓝牙耳机→耳机）。
- 材质/属性+品类：材质/属性是核心（羊绒服装→服装，材质"羊绒"；纯棉毛巾→毛巾，材质"纯棉"；真皮包包→包包，材质"真皮"）。这种组合里，前面的材质/属性比后面的品类更重要，必含词要保留材质/属性。
- 通用词（用品/商品/产品/物品）：限定词+通用词整体（万圣节用品→万圣节用品）。
- 节日/主题+品类：整体（圣诞装饰→圣诞装饰）。
- 系列名+品类：取品类（迪士尼公仔→公仔）。
- 只有系列名：猜最常见品类+系列名放必含词（字里行间系列→笔记本，必含"字里行间"）。
- 只有场景/平台词：场景词放入scene；coreProduct使用通用品类"商品"，但猜测品类不能进入requiredKeywords。跨境→coreProduct:"商品"，scene:["跨境"]，requiredKeywords:["跨境"]；欧美、亚马逊同理。
- 品牌：只取品类（babycare湿巾→湿巾）。

2. modifiers 修饰词
- style：款式/核心特征/功能结构（挖掘机、工程车、透明、加厚、折叠、USB口、防水、耐磨）。
- material：真实材质（PVC、硅胶、不锈钢、棉麻、羊绒、纯棉、尼龙、牛津布、真皮）。
- crowd：人群（女、男、儿童、宝宝、成人、学生）。
- scene：场景/平台（跨境、亚马逊、Temu、Shein、外贸、欧美爆款）。
- brand：品牌数组。
防水、防刮、耐磨、折叠、加厚、USB口、充电口属于功能/结构，放入style，不属于material。

3. expandedKeywords 扩展词（3~6个，宁缺毋滥）
- 第一个必须是原词本身。
- 每个扩展词必须包含核心品类词。
- 核心特征词不能换，可以换同义词但不能换类别。
- 只能换：同义词/近义词替换、属性词替换、平台词替换、品牌+不同规格。
- 品牌/系列/节日场景：每个扩展词都必须带品牌名/系列名/节日名。
- 行业大类词的扩展词必须是商家会写在标题里的具体产品词，不能全是行业词。
- 只有场景/平台词时，第一个扩展词保持原词；其余可组合"商品/产品/货源"，但每个词都必须保留原场景/平台词。
- 想不出精准同义词就少扩展，2个也可以，不能硬凑不同类产品。

4. expandedTokenGroups 扩展词拆词组
每个扩展词拆成2~4个词，品牌/系列/平台/品类/功能作为独立词；只有场景/平台词时原词允许只拆成1个词。长度与expandedKeywords一一对应。格式：{"word":"完整词","tokens":["词1","词2"]}。所有word和tokens去除前后空格。

5. requiredKeywords 必含词（第一个是主检索锚点）
- 先判断主检索锚点再决定顺序，禁止固定按原词顺序输出。
- 具体品类优先：大码连衣裙→["连衣裙","大码"]；学生双肩包USB口防水→["双肩包","USB口","防水","学生"]；儿童运动鞋→["运动鞋","儿童"]；红色保温杯→["保温杯","红色"]。
- 限定词决定商品本质时，限定词优先：毛绒玩具→["毛绒","玩具"]；益智玩具→["益智","玩具"]；羊绒服装→["羊绒","服装"]；万圣节用品→["万圣节","用品"]。
- 宽泛品类：玩具、服装、用品、商品、产品、百货、配件、装饰、设备、器材。具体品类：连衣裙、双肩包、手机壳、麻将包、运动鞋、保温杯、数据线、毛巾等。
- 普通尺寸、人群、颜色、营销词不能仅因出现在前面就成为主检索锚点。
- 确定主检索锚点后，其余词固定排序：主检索锚点 → coreProduct → 核心功能/结构 → 材质/关键属性 → 人群 → 场景/平台 → 品牌/系列。
- 若第一个不是coreProduct而是材质、功能、主题等限定词，必须与coreProduct绑定检索：毛绒玩具至少同时包含"毛绒"+"玩具"。
- 品牌按主检索锚点规则排序再加入品牌；复合产品名完整优先；行业大类词取核心可检索品类；材质+品类按锚点规则；只有场景/平台词只放原场景/平台词。

6. 英文词
通用产品词→中文（teethers→牙胶）；品牌/专有名→保留英文；USB统一输出为"USB"，禁止输出带空格的变体。

import json, re
from datetime import datetime, timedelta

def main(text, keyword, category_ids):
    s = text.find('{'); e = text.rfind('}')
    if s < 0 or e <= s: raise ValueError('LLM输出中未找到JSON')
    d = json.loads(text[s:e+1])
    m = d.get('modifiers') or {}
    w = []
    for k in ('style','material','crowd','scene'):
        for v in m.get(k) or []:
            if isinstance(v, str) and v.strip() and v.strip() not in w:
                w.append(v.strip())
    brand = d.get('brand') or next(
        (v.strip() for v in m.get('brand') or [] if isinstance(v, str) and v.strip()), '')

    ids = []
    for v in category_ids or []:
        x = str(v or '').strip()
        if x and x not in ids: ids.append(x)

    q = keyword or ''
    bd = ed = None
    z = re.search(r'(?:近|最近|过去|近来)[ ]*([0-9]+)[ ]*(?:天|日)', q)
    if z and int(z.group(1)) > 0:
        t = datetime.now().date()
        bd = (t - timedelta(days=int(z.group(1)))).strftime('%Y-%m-%d')
        ed = t.strftime('%Y-%m-%d')

    bp = ep = None
    z = re.search(r'(?:价格[ ]*)?([0-9]+(?:[.][0-9]+)?)[ ]*(?:-|~|～|至|到)[ ]*([0-9]+(?:[.][0-9]+)?)[ ]*(?:元|块)', q)
    if z:
        bp, ep = sorted((float(z.group(1)), float(z.group(2))))
    else:
        z = re.search(r'(?:价格[ ]*)?(?:小于|低于|少于|不超过|至多|最多)[ ]*([0-9]+(?:[.][0-9]+)?)[ ]*(?:元|块)|(?:价格[ ]*)?([0-9]+(?:[.][0-9]+)?)[ ]*(?:元|块)[ ]*(?:以下|以内|及以下|之内)', q)
        if z: ep = float(z.group(1) or z.group(2))
        z = re.search(r'(?:价格[ ]*)?(?:大于|高于|不少于|不低于|至少|最低)[ ]*([0-9]+(?:[.][0-9]+)?)[ ]*(?:元|块)|(?:价格[ ]*)?([0-9]+(?:[.][0-9]+)?)[ ]*(?:元|块)[ ]*(?:以上|起|及以上)', q)
        if z: bp = float(z.group(1) or z.group(2))

    a = {
        'requiredKeywords':   d.get('requiredKeywords') or [],
        'expandedKeywords':   d.get('expandedKeywords') or [],
        'expandedTokenGroups':d.get('expandedTokenGroups') or [],
        'modifiers':          '、'.join(w),
        'brand':              brand
    }
    query = {
        'keyWord':             q.strip(),
        'categoryIdList':      ids,
        'aiKeyword':           a,
        'beginOfferCreateTime':bd or '',
        'endOfferCreateTime':  ed or '',
        'beginPrice':          bp,
        'endPrice':            ep
    }
    req = {'pageIndex': 1, 'pageSize': 30, 'query': query}
    return {
        'req':       req,
        'jsonText':  json.dumps(d, ensure_ascii=False),
        'pageIndex': 1,
        'pageSize':  30,
        'query':     query
    }

import json

def main(result):
    a = result
    header = '| 主图 | 标题 | 价格 | 起订 | 销量 | 发货 | 地区 | 公司 | 类目 |'
    sep    = '| --- | --- | --- | --- | --- | --- | --- | --- | --- |'
    rows   = [
        '| ![](' + str(x.get('image') or '') + ') | ['
              + str(x.get('title') or '') + ']('
              + str(x.get('shopUrl') or '') + ') | '
              + str(x.get('price') or x.get('consignPrice') or '') + ' | '
              + str(x.get('quantityBegin') or '') + ' '
              + str(x.get('unit') or '') + ' | '
              + str(x.get('salesVolume') or x.get('saleQuantity') or '') + ' | '
              + str(x.get('deliveryTime') or '') + ' | '
              + str(x.get('province') or '') + ' '
              + str(x.get('city') or '') + ' | '
              + str(x.get('company') or '') + ' | '
              + str(x.get('levelName') or '') + ' |'
        for x in a
    ]
    body = chr(10).join(rows)
    markdown = '## 共 ' + str(len(a)) + ' 条' + chr(10)*2 + header + chr(10) + sep + chr(10) + body
    return {'markdown': markdown, 'count': len(a), 'raw': a}
核心渲染点：主图用 ![]()、标题用 [](shopUrl) 链接。前端 streamdown 会把 ![]() 包成可点击放大的图册组件，把 []() 包成可点击的跳转链接。

故障与修复

按时间倒序记录本次构建过程中的所有真实问题、原因、修复方式与教训。

#现象原因修复
5 上游 LLM Provider "Model is disabled"
工具调用返回 request failed: Model is disabled。		 Dify 当前工作区某个 LLM Provider 临时禁用，与主 Chatflow 逻辑无关。 下游直接调接口已能跑通；继续验证 query 正确性；待 Provider 恢复后跑回归。
4 第二轮不调工具
用户问"再筛选只要大码连衣裙类目的"，模型直接基于上一轮 30 条判断"没有符合商品"。		 指令虽要求合并条件，但未显式禁止"基于历史表格自行筛选"。 指令 v2：增加"所有条件变化必须重新调用工具"+"禁止本地筛选历史表格"。两轮回归确认均触发了 1688selector。
3 类目 ID 缺失
下游搜索请求 categoryIdList 为空，导致商品类目错乱。		 原代码读 data["categoryTree"]，但 1688 接口真实返回字段是 result。 Code 节点改为 data.get("categoryTree") or data.get("result") or []，并兼容字符串/字典/列表多种返回形态。
2 主 Chatflow 聊天记忆关闭
第二轮追问时没有上下文继承条件。		 默认 Agent 节点"记忆"开关是关闭的。 开启 Agent 记忆、记忆窗口。窗口曾尝试改 20 但持久化为 50，不影响核心功能。
1 主 Chatflow 仅截取商品词
用户输入 "近30天上架的连衣裙"，下游 query 变成 "连衣裙"，时间和价格被吃掉。		 原设计让 Chatflow 自行"提取关键词"再传下游。 改为"单轮原文透传"，仅在上下文追问时合并条件。下游天然拿到完整 query。

教训

  • Chatflow 与 Workflow 职责要清晰：前者管会话上下文，后者管业务执行。
  • 无状态 Workflow 不应假设调用方记得上次条件，所有追问条件必须在调用方合并完整后再传。
  • 指令要给模型"禁止动作"，明确禁止项比罗列允许项更稳。
  • 渲染层（Markdown 表格里的图片）能力应作为链路验收证据之一。
  • 归档时把每个节点的 prompt / Code / 参数都原样保留下来，避免后续只能凭印象重建。
