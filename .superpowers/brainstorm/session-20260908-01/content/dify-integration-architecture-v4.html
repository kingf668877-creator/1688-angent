三栏选品工作台如何连接 Dify

推荐把 Dify 当作“工作流后端”，不要嵌入或操控它自带的 Web 页面。两个页面可以并存，并使用同一条已发布工作流。

推荐数据流
你的三栏页面
会话 + 对话 + 商品 Tabs
发送问题、展示进度、筛选与导出
→
你的后端代理
保管密钥 + 转发请求
保存会话、消息、结果集和 Tab 状态
→
Dify 工作流 API
1688 选品库
分析需求、五层检索、去重排序、返回 JSON
1. 用户提问
中间对话区发送关键词和筛选条件
2. 调用工作流
后端调用已发布的 Dify 工作流
3. 解析输出
读取 summary、queries、finalItems
4. 创建 Tab
每次结果形成独立 Tab 并持久保存

三种连接方式

A

后端代理调用（推荐）

浏览器只访问你自己的接口，Dify API 密钥保存在服务端。可稳定实现登录、历史会话、多 Tab、权限和失败重试，适合正式产品。

B

浏览器直接调用

开发最快，但会暴露 Dify 密钥，还可能遇到跨域限制。只适合临时本地验证。

C

嵌入 Dify WebApp

可用 iframe 看原页面，但难以控制其内部消息、结果和样式，也无法自然同步右侧商品 Tab，不建议采用。

需要区分的两类数据

工作流运行记录仍会进入 Dify 的日志，方便你在 Dify 中调试；产品侧会话记录由你的应用保存，用来驱动左侧历史、中间消息和右侧结果 Tab。它们调用同一条工作流，但不依赖 Dify 自带 WebApp 的页面状态。

关键产品选择

A

后续问题继承上次条件（推荐）

例如先搜“男士外套”，再说“只看 50 元以内”，系统自动理解为在上一批条件上继续筛选。

B

每次提问独立搜索

每条问题都从零开始，不读取上次条件。实现简单，但对话感较弱。
